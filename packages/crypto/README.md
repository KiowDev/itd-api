# @itd-api/crypto

Шифрование отдельных участков текста для
[`itd-api`](https://github.com/KiowDev/itd-api).

[Руководство](https://kiowdev.github.io/itd-api/packages/crypto) ·
[API из TSDoc](https://kiowdev.github.io/itd-api/api/generated/crypto/)

В одном поле могут одновременно находиться открытый текст и несколько независимо
зашифрованных участков. При отправке плагин помещает отдельные участки в транспортные
контейнеры, а целое поле без внутренних границ разметки кодирует без обёртки. После ответа
он собирает готовый текст в `decoded`. Исходные значения ответа сервера остаются без изменений.

> Встроенные алгоритмы обеспечивают обфускацию, но не криптографическую секретность.
> Для настоящей защиты сначала зашифруйте данные надёжным алгоритмом, а затем передайте
> результат этому плагину.

## Установка

```sh
npm i itd-api @itd-api/crypto
```

Пакет работает во всех средах основного клиента и не требует модулей Node.js.

## Первый пример

```ts
import { ItdClient } from 'itd-api';
import { crypt } from '@itd-api/crypto';

const itd = new ItdClient({ auth: process.env.ITD_TOKEN });
itd.use(crypt());

const post = await itd.posts.create({
  content: 'видно секрет видно',
  spans: [
    { type: 'bold', offset: 6, length: 6 },
    { type: 'crypto', cipher: 'invisible', offset: 6, length: 6 },
  ],
});

post.content;                 // исходное транспортное значение от сервера
post.spans;                   // разметка в координатах content
post.decoded?.content?.text;  // 'видно секрет видно'
post.decoded?.content?.spans; // разметка готового текста
```

`content` содержит именно то, что сохранил сервер: открытые части и невидимый контейнер.
Для отображения расшифрованного результата используйте `decoded.content.text`, а для его
форматирования — `decoded.content.spans`.

```ts
post.decoded = {
  content: {
    text: 'видно секрет видно',
    spans: [
      { type: 'bold', offset: 6, length: 6 },
      {
        type: 'crypto',
        cipher: 'invisible',
        cipherId: 0,
        offset: 6,
        length: 6,
      },
    ],
  },
};
```

## Как выбрать участки

У постов криптографические диапазоны можно задавать прямо в обычном массиве `spans`:

```ts
await itd.posts.create({
  content: 'первый секрет и второй секрет',
  spans: [
    { type: 'crypto', cipher: 'invisible', offset: 7, length: 6 },
    { type: 'crypto', cipher: 'my-cipher', offset: 22, length: 6 },
  ],
});
```

Поле `cipher` принимает имя или числовой идентификатор шифра. Разметка `crypto` служит только
плагину: перед отправкой она удаляется и не попадает в серверный массив.

Если текст собирается через `MarkupBuilder`, смещения можно не считать вручную. Для
криптографического участка используется универсальный метод `span()`:

```ts
import { post } from 'itd-api';
import { CipherName } from '@itd-api/crypto';

await itd.posts.create(
  post().markup((m) =>
    m
      .text('Открыто, ')
      .span('первый секрет', {
        type: 'crypto',
        cipher: CipherName.Invisible,
      })
      .text(', снова открыто, ')
      .span(
        (secret) => secret.bold('второй секрет'),
        {
          type: 'crypto',
          cipher: CipherName.Invisible,
        },
      ),
  ),
);
```

`MarkupBuilder` автоматически рассчитывает `offset` и `length`. Вложенная обычная
разметка также сохраняется: второй участок в примере одновременно зашифрован и выделен
жирным.

Для комментариев, универсального API и программно рассчитанных диапазонов используйте
настройки вызова:

```ts
await itd.posts.comment('post-id', 'видно один и два видно', {
  extensions: {
    crypto: {
      spans: [
        { cipher: 'invisible', offset: 6, length: 4 },
        { cipher: 5, offset: 13, length: 3 },
      ],
    },
  },
});
```

Оба способа можно сочетать. Все диапазоны одного поля должны быть непустыми,
непересекающимися и находиться внутри исходной строки.


## Поле целиком и несколько полей

Свойство `encrypt` шифрует все переданные непустые текстовые поля операции целиком:

```ts
await itd.users.updateMe(
  { displayName: 'Скрытое имя', bio: 'Скрытая подпись' },
  { extensions: { crypto: { encrypt: 'beecrypt' } } },
);
```

Чтобы выбрать только одно поле операции с несколькими полями, передайте его полный
диапазон:

```ts
await itd.users.updateMe(
  { displayName: 'Открытое имя', bio: 'Скрытая подпись' },
  {
    extensions: {
      crypto: {
        spans: [
          { field: 'bio', cipher: 'beecrypt', offset: 0, length: 16 },
        ],
      },
    },
  },
);
```

У операции с несколькими текстовыми полями `field` обязателен. `encrypt` нельзя сочетать
со `spans`; пустой `spans: []` также является ошибкой.

## Поддерживаемые поля

| Операция | Текстовые поля | Связанная разметка |
|---|---|---|
| `posts.create`, `posts.update`, `posts.repost` | `content` | `spans` |
| `posts.comment`, `comments.reply`, `comments.update` | `content` | `spans`, если вернул сервер |
| `users.createProfile` | `displayName` | нет |
| `users.updateMe` | `displayName`, `bio` | нет |

При чтении проверяются `content`, `displayName`, `bio` и `preview` во всём дереве ответа:
в постах, комментариях, профилях, авторах, пользователях и уведомлениях.

Невидимые маркеры подтверждены только для `content` и `preview`. Поэтому `invisible` и
другие алгоритмы с `requiresInvisibleAlphabet: true` нельзя применять к `displayName` и
`bio`. Для них используйте шифр целого поля, например `beecrypt`.

## Взаимодействие с обычной разметкой

Визуальные типы `bold`, `italic`, `underline`, `strike`, `spoiler`, `monospace` и `quote`
могут пересекать зашифрованный участок любым способом. Плагин делит участок по внутренним
границам форматирования, отправляет несколько соседних контейнеров, а после чтения
восстанавливает исходные координаты.

Семантические типы `link`, `mention` и `hashtag` нельзя пересекать с зашифрованным
участком. Такой запрос завершится локальной ошибкой до обращения к сети.

## Что находится в `decoded`

- исходные строки и серверные `spans` не изменяются;
- `decoded[field].text` содержит открытый и расшифрованный текст одной строкой;
- `decoded[field].spans` использует координаты этой строки;
- `CryptoSpan` содержит имя и стабильный числовой идентификатор алгоритма;
- соседние участки одного шифра объединяются;
- повреждённый или неизвестный контейнер остаётся в исходном виде;
- поле без успешной расшифровки не добавляется;
- если находок нет, свойство `decoded` не создаётся.

Плагин обходит страницы и вложенные модели:

```ts
for await (const post of itd.posts.iterate({ tab: 'following' })) {
  console.log(post.decoded?.content?.text);
  console.log(post.originalPost?.decoded?.content?.text);
  console.log(post.comments?.[0]?.decoded?.content?.text);
}
```

Для нормализованных событий подключите тот же экземпляр отдельно:

```ts
const crypto = crypt();
itd.use(crypto);
itd.notifications.events.use(crypto);

itd.notifications.events.on('notification', ({ notification }) => {
  console.log(notification.decoded?.preview?.text);
});
```

Автоматическую расшифровку можно настроить глобально и для отдельного вызова:

```ts
itd.use(crypt({ decrypt: false }));

await itd.posts.get('post-id', {
  extensions: { crypto: { decrypt: true } },
});
```

## Встроенные шифры

| Имя | Идентификатор | Отправка | Фрагменты | Невидимый алфавит |
|---|---:|---:|---:|---:|
| `invisible` | 0 | да | да | нужен |
| `beecrypt` | 1 | да | нет | не нужен |

Идентификатор записывается в транспортный контейнер фрагмента и возвращается в
`CryptoSpan.cipherId` для любого распознанного участка. Для пользовательских алгоритмов
используйте значения начиная с `2`.

### `invisible`

Алфавит состоит из шести невидимых символов `U+206A`…`U+206F`. Каждый байт UTF-8
записывается четырьмя символами в системе счисления по основанию 6. Целое поле без внутренних
границ visual-разметки хранит только нагрузку. Для отдельного фрагмента общий контейнер хранит
маркер начала, идентификатор шифра, нагрузку и маркер конца.

Для идентификатора `0` служебная часть контейнера занимает девять кодовых единиц UTF-16. При
лимите `content` в 1000 позиций целое поле вмещает до 250 байт исходного текста, а отдельный
фрагмент с контейнером — до 247 байт.

Низкоуровневые функции алгоритма доступны напрямую:

```ts
import { decodeInvisible, encodeInvisible, stripInvisible } from '@itd-api/crypto';

const encoded = encodeInvisible('секрет');
decodeInvisible(encoded);                   // 'секрет'
stripInvisible(`обычный текст${encoded}`);  // 'обычный текст'
```

### `beecrypt`

Текст переводится в UTF-8, затем в base64, а пары битов символов base64 заменяются
буквами: `00 → ж`, `01 → ъ`, `10 → Ж`, `11 → Ъ`.

```ts
import { decodeBeeCrypt, encodeBeeCrypt } from '@itd-api/crypto';

const encoded = encodeBeeCrypt('A'); // 'ъъжъъъжъжЪЪъжЪЪъ'
decodeBeeCrypt(encoded);             // 'A'
```

Шифротекст виден целиком, поэтому алгоритм применяется только ко всему полю. Внутренние
границы визуальной разметки в таком поле отклоняются: без отдельных контейнеров их нельзя
восстановить.

## Пользовательский шифр

```ts
import { BUILT_IN_CIPHERS, crypt, type Cipher } from '@itd-api/crypto';

const brackets: Cipher = {
  name: 'brackets',
  id: 5,
  supportsFragments: true,
  encode: (text) => `[${text}]`,
  decode: (encoded) => {
    if (!encoded.startsWith('[') || !encoded.endsWith(']')) return null;
    return encoded.slice(1, -1);
  },
};

itd.use(crypt({
  ciphers: [...BUILT_IN_CIPHERS, brackets],
}));
```

Переданный `ciphers` заменяет встроенный реестр, поэтому для сохранения совместимости
встроенные алгоритмы добавлены явно.

Требования к пользовательскому алгоритму:

- уникальные непустые `name` и неотрицательный безопасный целочисленный `id`;
- `encode(text)` возвращает строку и отсутствует у режима только для чтения;
- `decode(text)` возвращает исходный текст либо `null`;
- `supportsFragments: true` разрешает отдельные участки;
- `requiresInvisibleAlphabet: true` ограничивает доступные поля.

Полное поле без внутренних границ visual-разметки отправляется как результат `encode()` без
контейнера. Фрагментный алгоритм получает только точную нагрузку внутри общего контейнера и не
ищет границы самостоятельно. Его результат не должен содержать общие маркеры начала или конца.

Алгоритм, который не поддерживает отдельные участки, не задаёт `supportsFragments`. При чтении
bare whole-field форматы проверяются по порядку реестра; при отправке шифр всегда выбирается явно.

## Подключаемые операции

Подключаемый модуль может объявить текстовые поля в метаданных операции:

```ts
annotations: {
  crypto: {
    requestFields: [{
      name: 'message',
      spansField: 'spans',
      maxLength: 2000,
      preservesInvisibleAlphabet: true,
    }],
  },
}
```

Одно имя можно передать строкой. Тогда поле считается сохраняющим невидимый алфавит, но
не получает связанной разметки и известного ограничения длины.

## Ошибки и ограничения

`CryptError` возникает до сетевого запроса при неизвестном шифре или поле, неверном либо
пересекающемся диапазоне, конфликте с семантической разметкой, неподдерживаемом режиме,
неподходящем алфавите, маркере внутри нагрузки или превышении лимита длины.

Сервер считает длину `content` в кодовых единицах UTF-16. Подтверждённый предел — 1000;
плагин проверяет его после преобразования. Временно тот же предел применяется к
`displayName` и `bio`.

Одна ASCII-буква занимает в `invisible` четыре позиции, кириллическая — восемь,
четырёхбайтовый эмодзи — шестнадцать. Каждое деление по визуальной границе добавляет ещё
одну девятипозиционную служебную часть контейнера.
