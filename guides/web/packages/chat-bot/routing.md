# Модули и маршруты

Когда у бота появляются команды для разных задач, удобно держать их в разных файлах.
Например, команды поддержки можно собрать в одном модуле, а команды для сотрудников — в другом.
В точке запуска останется подключить нужные модули и при необходимости распределить их по чатам.

## Модули на `ChatComposer`

`ChatComposer` собирает обработчики одного модуля. В нём можно регистрировать команды, фильтры
и события чата так же, как на боте. Готовый модуль подключается через `bot.use()`.

```ts
import { ChatComposer } from '@itd-api/chat-bot';

const help = new ChatComposer();
help.command('помощь', (ctx) => ctx.reply('Напишите, чем вам помочь.'));
bot.use(help);
```

Модуль использует префиксы команд бота. Подключать модуль можно и к другой ветке через её `use()`.

## Ветки и порядок выполнения

`command()`, `hears()` и `on()` для событий чата возвращают ветку, в которую проходят только
подходящие события. Чтобы добавить несколько независимых условий, регистрируйте их на одном
модуле. Чтобы совместить условия, добавьте вторую проверку к первой ветке.

`use()` добавляет обработчики в порядке регистрации. Если обработчик вызвал `await next()`,
цепочка продолжается. Без этого вызова следующие обработчики для данного события пропускаются.
Например, так можно проверить права перед выполнением команды:

```ts
const report = bot.command('отчёт');

report.use(async (ctx, next) => {
  if (ctx.senderId !== adminId) {
    await ctx.reply('У вас нет доступа к отчёту.');
    return;
  }
  await next();
});

report.use((ctx) => ctx.reply('Отчёт готов.'));
```

## Своё условие через `filter()`

`filter()` принимает функцию, которая возвращает `true` или `false`, в том числе асинхронно.
Например, из событий о действиях собеседника можно выбрать только запись видео:

```ts
import { ChatActionType, ChatUpdateType } from 'itd-api';

bot.on(ChatUpdateType.Typing).filter(
  (ctx) => ctx.update.action === ChatActionType.RecordVideo,
  (ctx) => console.log('Собеседник записывает видео', ctx.chatId),
);
```

## Маршруты по чатам

`router(selector)` выбирает, какой группе обработчиков передать событие. Функция `selector`
возвращает ключ, например ID чата. `route(key)` регистрирует ветку для этого ключа,
а `otherwise()` — запасную ветку. Один роутер можно передать нескольким модулям,
чтобы каждый зарегистрировал свои команды:

```ts
const chats = bot.router((ctx) => ctx.chatId);

function registerSupport(routes: typeof chats) {
  routes.route('support-chat-id').command('помощь', (ctx) => ctx.reply('Опишите проблему.'));
}

function registerTeam(routes: typeof chats) {
  routes.route('team-chat-id').command('статус', (ctx) => ctx.reply('Бот на связи.'));
}

registerSupport(chats);
registerTeam(chats);

chats.otherwise().command('помощь', (ctx) => ctx.reply('Этот чат не настроен для поддержки.'));
```

## Две ветки через `branch()`

`branch()` выбирает одну из двух цепочек по условию. Например, можно подключить
одни команды в рабочем чате и другие в остальных:

```ts
bot.branch((ctx) => ctx.chatId === teamChatId, teamCommands, publicCommands);
```

Здесь `teamCommands` и `publicCommands` — модули `ChatComposer`. Готовые функции-обработчики
тоже подходят. Если третьего аргумента нет, при ложном условии бот продолжает общую цепочку.

## Ошибки отдельной ветки

`errorBoundary()` создаёт ветку с собственным обработчиком ошибок. Добавляйте команды и middleware
в возвращённую ветку, чтобы их ошибки попадали в этот обработчик:

```ts
const safe = bot.errorBoundary(({ error }) => console.error('Ошибка команды', error));
safe.command('статус', (ctx) => ctx.reply('Бот на связи.'));
```

`next()` в обработчике ошибки продолжает внешнюю цепочку. При включённом [сохранении номера события](./runtime.md#checkpoint)
событие с перехваченной ошибкой не считается обработанным.
