# Порядок выполнения запроса

## Уровни выполнения

Клиент различает:

- **операцию** — один логический HTTP-запрос с постоянным `operationId`;
- **попытку** — одно обращение к транспорту, включая повтор после `5xx`, `429`
  или успешного обновления авторизации.

`OperationTransformer` вызывается один раз и работает с результатом публичного метода.
`AttemptInterceptor` вызывается для каждой сетевой попытки и получает сырой `Response`.

## Порядок выполнения

```text
плагины операции
  → описание операции
    → выбор сервиса
      → предварительная подготовка авторизации
        → повторные попытки
          → обновление авторизации после 401
            → подготовка авторизации к попытке
              → очередь конечного URL.origin
                → номер попытки
                  → актуальные заголовки авторизации
                    → перехватчики попытки и транспорт
```

При возврате результата транспорт снимает HTTP-обёртку, операция преобразует тело в
предметную модель, затем значение возвращается плагинам операции. Ответ, который плагин
вернул без `next()`, считается готовым.

При отключённом ограничителе стадия очереди отсутствует. Номер присваивается после ожидания
очереди и считает фактические обращения к транспорту. После `401` исходная операция получает
следующий номер попытки, а `auth.refresh` выполняется как отдельная операция:

```text
users.me: attempt 1 → 401
auth.refresh: attempt 1 → 200
users.me: attempt 2 → 200
```

## Инварианты

- Локальный результат `OperationTransformer` не входит в очередь и не расходует лимит.
- Пауза между повторами не занимает место в очереди; новая попытка планируется заново.
- Сервис и разовый `baseUrl` разрешаются до выбора очереди. Ключом служит пара «итоговый
  `URL.origin` — серверный бакет». Разные имена одного адреса делят ограничитель, а операции
  из разных бакетов не мешают друг другу. Ключ не меняется между попытками.
- Очередь двухуровневая: задача занимает слот своего бакета, затем общий слот направления.
  Пауза бакета удерживает её до захвата общего слота, поэтому притормозивший счётчик
  не занимает общую ёмкость, а суммарная одновременность остаётся равна `concurrency`.
- Подготовка авторизации не занимает место в очереди. Отложенный вход и предварительное
  обновление выполняются до retry исходного запроса, но сами проходят тот же pipeline как
  отдельные операции со своими `operationId` и `RetrySafety`.
- Заголовки авторизации читаются после ожидания очереди, перед транспортом.
- После `401` авторизация обновляется не более одного раза.
- `operationId`, HTTP-метод и `RetrySafety` встроенных операций берутся из единого каталога.
- Составной метод может выполнить несколько операций; каждая проходит плагины отдельно.
- После начала `dispose()` новые пользовательские операции запрещены. Только внутренние
  запросы отправки накопленной телеметрии могут завершиться.

## Выбор точки расширения

Используйте `operations.use()` для кэширования, шифрования, подмены или преобразования
результата. Используйте `attempts.use()`, если нужны итоговый URL, заголовки, подпись запроса,
сетевые метрики или сырой `Response` каждой попытки.

Подробные типы и примеры находятся в [руководстве по плагинам](../plugins/README.md).
